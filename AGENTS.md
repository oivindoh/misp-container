## Image

The `Dockerfile` builds the images from these stages:

| Stage | What it holds |
|---|---|
| php-base | Common runtime packages |
| misp-source | Clone MISP, set permissions |
| composer | PHP dependencies, pinned by files/composer.lock |
| php-build | Native PHP extensions, built from pinned sources |
| uv | Python package installer (pinned) |
| python | Python packages of misp_container and of MISP's scripts |
| caddy-bin | The caddy binary for the web pod's caddy container |
| final | Runtime image (non-root) |
| modules | MISP enrichment/import/export/action modules |

Each role of the main image is a module of the package, run under the image's tini entrypoint; the chart's workloads start them so:

## Periodic work

MISP's own scheduler never runs. The task runner (`python3 -m misp_container.task <task>`) does each piece of periodic work, from the CronJobs of the `cronjobs` component (docs/kubernetes.md, Periodic tasks):

| Task | Does | Runs | CronJob schedule (component) |
|---|---|---|---|
| `cache-feeds` | Cache every feed | `cake Server cacheFeed 1 all` | `20 2 * * *` (`cronjobs`) |
| `fetch-feeds` | Fetch every enabled feed | `cake Server fetchFeed 1 all` | `30 2 * * *` (`cronjobs`) |
| `cache-servers` | Cache the events of every server | `cake Server cacheServer 1 <id>` | `40 2 * * *` (`cronjobs`) |
| `update-galaxies` | Update MISP's bundled galaxies | `cake Admin updateGalaxies false` | `0 3 * * *` (`cronjobs`) |
| `update-taxonomies` | Update MISP's bundled taxonomies | `cake Admin updateTaxonomies` | `10 3 * * *` (`cronjobs`) |
| `update-warninglists` | Update MISP's bundled warninglists | `cake Admin updateWarningLists` | `20 3 * * *` (`cronjobs`) |
| `update-noticelists` | Update MISP's bundled noticelists | `cake Admin updateNoticeLists` | `30 3 * * *` (`cronjobs`) |
| `update-object-templates` | Update MISP's bundled object templates | `cake Admin updateObjectTemplates 1` | `40 3 * * *` (`cronjobs`) |
| `pull-servers` | Pull from every server with pull enabled | `cake Server pull 1 <id> full` | `*/5 * * * *` (`cronjobs`) |
| `push-servers` | Push to every server with push enabled | `cake Server push 1 <id> full` | `*/15 * * * *` (`cronjobs`) |
| `push-taxii` | Push to every enabled TAXII server | `cake Server push_taxii 1 all` | `7 * * * *` (`cronjobs`) |
| `sharing-group-blueprints` | Apply the sharing group blueprints | `cake Admin executeSGBlueprint all` | none |
| `workflow` | Run one ad-hoc workflow, by its ID | `cake Workflow executeAdHocWorkflow <id>` | none |
| `periodic-summary` | Send the daily, weekly (Mondays) and monthly (the first) summaries users subscribed to | `cake Server sendPeriodicSummaryToUsers` | `0 6 * * *` (`cronjobs`) |
| `check-user-validity` | Report every account as valid or invalid at the OIDC or LDAP provider | `cake Admin checkUserValidity` | none |
| `block-invalid-users` | Disable the accounts the OIDC or LDAP provider no longer backs | `cake Admin blockInvalidUsers` | none |

## Kubernetes: the Helm chart in `deploy/chart/`

Values of the misp chart. The comment above each top-level key describes it; docs/kubernetes.md and AGENTS.md take their tables from these comments. A key with enabled: false is a component: an optional part that a release switches on.

| Template | Renders, every component on | Note |
|---|---|---|
| `configmap-env.yaml` | ConfigMap `misp-env` | misp-env: files/base.env, then the env value. Every MISP pod reads it; its checksum rolls the Deployments. With databaseCA, DB_SSLROOTCERT names the certificate's mount. |
| `configmap-orgs.yaml` | ConfigMap `misp-orgs` | Declarative org config for the org-sync Job (orgSync.orgs; format: deploy/orgs.yaml.example). |
| `cronjobs-housekeeping.yaml` | CronJob `housekeeping-audit-logs`, CronJob `housekeeping-jobs`, CronJob `housekeeping-logs` | The housekeeping component: nightly batched deletes of old rows in jobs, logs and audit_logs (python3 -m misp_container.housekeeping). Autovacuum reclaims the space. Retention is a policy choice: HOUSEKEEPING_<TABLE>_DAYS in env. |
| `cronjobs.yaml` | CronJob `cache-feeds`, CronJob `cache-servers`, CronJob `fetch-feeds`, CronJob `periodic-summary`, CronJob `pull-servers`, CronJob `push-servers`, CronJob `push-taxii`, CronJob `update-galaxies`, CronJob `update-noticelists`, CronJob `update-object-templates`, CronJob `update-taxonomies`, CronJob `update-warninglists` | The cronjobs component: the periodic tasks, run by the task runner in the main image (python3 -m misp_container.task <task>), one CronJob per entry of cronjobs.tasks with a schedule and one per workflow ID in cronjobs.workflows. Each runs MISP's console in its pod, so the periodic work never waits in the workers' queues. |
| `deployment-metrics.yaml` | Deployment `metrics` | Prometheus exporter on port 9191: MISP's database, the job queues in Redis and the sync partners (docs/metrics.md). It reads MISP's data and never changes it. |
| `deployment-modules.yaml` | Deployment `modules` | misp-modules: the enrichment, import, export and action modules MISP calls over HTTP on port 6666. A distroless image without a shell, as UID 65532. |
| `deployment-web.yaml` | Deployment `web` | MISP's web tier: PHP-FPM (127.0.0.1:9002) and a caddy sidecar that serves the static files and passes the rest to PHP-FPM over FastCGI (port 8080). Replicas scale freely: each pod renders its own app/Config and waits for the configure Job. |
| `deployment-worker.yaml` | Deployment `worker` | Scalable job workers -- safe to run multiple replicas. MISP's own scheduler never runs: periodic tasks are Kubernetes CronJobs (the cronjobs component). |
| `httproute.yaml` | HTTPRoute `misp` | The httpRoute component: an HTTPRoute for a Gateway API implementation, in place of the ingress. caddy takes the client address from X-Forwarded-For, right to left, past TRUSTED_PROXY_CIDR: set that in env to the Gateway's proxy pods. |
| `ingress.yaml` | Ingress `misp` | The ingress component: an Ingress to the web Service. The default annotation makes the haproxy ingress replace X-Forwarded-For with the address it sees, so only that address reaches caddy (docs/kubernetes.md, Client addresses). Behind another load balancer, that is the balancer's address unless it speaks the PROXY protocol to HAProxy. |
| `job-configure.yaml` | Job `configure-<revision>` | One-shot configuration: schema, settings, admin user, GPG, auth. Web and worker pods wait until this Job has set MISP.live=true and recorded their image version, so the order of the rollout does not depend on the tool that applies the chart. Each release revision has its own Job, because a Job's pod template cannot change; a run on a configured instance takes seconds. With the migrate component, the copy runs first, in an init container. |
| `job-org-sync.yaml` | Job `org-sync-<revision>` | Declarative org sync: applies the misp-orgs ConfigMap (orgs.yaml) through the MISP API once the configure run of its revision finished and web serves. Exits 0 at once when ADMIN_KEY is empty or orgs.yaml has nothing to apply. Each release revision has its own Job; Argo CD: a Sync hook in wave 3, recreated on every sync. |
| `networkpolicy.yaml` | NetworkPolicy `misp`, NetworkPolicy `misp-web`, NetworkPolicy `misp-metrics`, NetworkPolicy `misp-egress`, NetworkPolicy `misp-modules`, NetworkPolicy `misp-stores` | The networkPolicy component: NetworkPolicies for the pods of the release, for any CNI that enforces the Kubernetes NetworkPolicy API, Cilium included. Every pod template carries app.kubernetes.io/instance (the release) and app.kubernetes.io/part-of: misp, and every rule selects on them, so the pods of another release or an operator in the namespace keep their own rules. |
| `pdb.yaml` | PodDisruptionBudget `web`, PodDisruptionBudget `worker` | One voluntary disruption at a time for web and worker. maxUnavailable, not minAvailable, so a single replica never blocks a node drain. |
| `postgres.yaml` | Service `postgres`, StatefulSet `postgres` | The postgres component: single-node PostgreSQL on a ReadWriteOnce claim, the database misp owned by DB_USER, UTF8, behind the Service postgres that DB_HOST names by default. |
| `pvc-attachments.yaml` | PersistentVolumeClaim `attachments` | Attachments and malware samples, org logos and custom images. Web and worker pods on different nodes write here, so the storage class must support ReadWriteMany. With attachments.claim: false (attachments in S3) the chart renders no claim. |
| `redis.yaml` | Service `redis`, Deployment `redis` | The redis component: a single Redis without persistence, so sessions and queued jobs do not survive a restart. The password is MISP_REDIS_PASSWORD. |
| `secrets.yaml` | Secret `misp-db`, Secret `misp-app`, Secret `misp-admin`, Secret `misp-migrate` | The Secrets follow their consumers: web and worker pods get misp-db and misp-app, never misp-admin; metrics gets two keys of misp-db and one of misp-app. Each is its file in files/ with the secrets value on top; with secrets.create: false the release supplies them. |
| `service-metrics.yaml` | Service `metrics` | The exporter on port 9191, for Prometheus to scrape. |
| `service-modules.yaml` | Service `modules` | misp-modules on port 6666, for MISP's enrichment, import, export and action calls. |
| `service-web.yaml` | Service `web` | MISP over HTTP: caddy in the web pods, port 8080. The ingress or HTTPRoute routes here. |
| `tests/test-misp.yaml` | Pod `misp-test` | helm test: checks a release from inside the cluster. It loads the login page through the web Service and, with ADMIN_KEY in misp-admin, calls the API as the admin and reads MISP.live. |

| Value | Is |
|---|---|
| `image` | The two images, with one tag. An empty tag is the chart's appVersion. The web pod's caddy container runs the misp image. |
| `imagePullSecrets` | Secrets with the registry credentials for the images, by name. |
| `nodeSelector` | Node selection for every pod of the release. |
| `tolerations` | Tolerations for every pod of the release. |
| `affinity` | Affinity for every pod of the release. |

| `configure` | The configure Job: schema, settings, admin user, GPG and auth, on every install and upgrade. |
| `web` | MISP's web tier: PHP-FPM and the caddy sidecar in each pod. Replicas scale freely. |
| `worker` | The background workers, which take their jobs from Redis. Replicas scale freely. |
| `metrics` | The Prometheus exporter (docs/metrics.md). |
| `modules` | misp-modules: the enrichment, import, export and action modules. |
| `orgSync` | The org-sync Job applies orgs, the content of orgs.yaml (deploy/orgs.yaml.example), through the API after each install and upgrade. It exits at once when ADMIN_KEY is empty. |
| `attachments` | Attachments, org logos and custom images on the claim attachments. Web and worker pods on different nodes write there, so the storage class must offer ReadWriteMany. For attachments in S3, set PLUGIN_S3_BUCKET_NAME in env and claim: false; org logos and custom images then stay in each pod. |

Components, each off by default:

| Component | Adds |
|---|---|
| `postgres` | Single-node PostgreSQL on a ReadWriteOnce claim. Leave it off for an external PostgreSQL (DB_HOST in env or connectionSecrets; CloudNativePG, StackGres, Percona and the like). |
| `redis` | Single Redis without persistence: sessions and queued jobs do not survive a restart. Leave it off for an external Redis (MISP_REDIS_HOST in env or connectionSecrets). maxmemory caps the data, under the memory limit: past it Redis refuses writes, and MISP's API calls and logins fail, because MISP keeps the feed and server caches, sessions and key use counters there. |
| `ingress` | An Ingress to the web Service. The default annotation makes the haproxy ingress replace X-Forwarded-For with the address it sees (docs/kubernetes.md, Client addresses). |
| `httpRoute` | An HTTPRoute for a Gateway API implementation, in place of the ingress. The Gateway must allow routes from this namespace; set TRUSTED_PROXY_CIDR in env to its proxy pods. |
| `networkPolicy` | NetworkPolicies for the release's pods, for any CNI that enforces the NetworkPolicy API, Cilium included: ingress from the release's own pods, DNS, HTTPS out, SMTP and LDAP. ingressNamespace holds the ingress or Gateway proxies, monitoringNamespace Prometheus; egress adds rules for the MISP pods, by default an external PostgreSQL and Redis. |
| `cronjobs` | The periodic tasks as CronJobs, each running MISP's console in its pod: tasks maps a task to its schedule, workflows a workflow ID to its schedule. The pod's PHP process has the workers' memory ceiling (WORKER_MEMORY_LIMIT, else PHP_MEMORY_LIMIT), which resources must hold. |
| `housekeeping` | Nightly deletes of old rows in jobs, logs and audit_logs (HOUSEKEEPING_<TABLE>_DAYS in env, defaults 2, 30 and 90). |
| `migrate` | A copy of an existing MySQL or MariaDB MISP into the database, before the configure Job runs (docs/migration.md). secret: entries on top of files/secrets-migrate.env for the misp-migrate Secret. volumes and volumeMounts: the source's attachments directory. |

## Settings: `files/misp-config/settings.yaml`

MISP settings in groups; each setting's env var is its name in upper case with dots as underscores (DEVELOPING.md, Settings Engine).

| Group | Holds |
|---|---|
| `minimum_config` | rendered into config.php by init, in every pod. MISP never reads SystemSetting::BLOCKED_SETTINGS from the database (salt, encryption key, password policy, python_bin, ca_path, tmpdir, attachments_dir, self_update, online_version_check, system_setting_db, GnuPG.binary, disable_local_feed_access), so those live here. |
| `db_enable` | toggle system_setting_db |
| `initialisation` | core instance settings |
| `critical` | always-enforced settings |
| `optional` | nice-to-have defaults |
| `gpg` | GnuPG settings |
| `s3` | S3 attachment storage (only applied when PLUGIN_S3_BUCKET_NAME is set, which also sets MISP.attachments_dir to s3://, env.py) |
| `proxy` | HTTP proxy settings (an empty Proxy.host means no proxy) |
| `custom_auth` | header authentication from a reverse proxy, no directory lookup (CUSTOM_AUTH_ENABLE=true turns it on; the CUSTOM_AUTH_* names are aliases, env.py) |
| `kafka` | Kafka pub/sub integration (PLUGIN_KAFKA_ENABLE=true turns it on) |
| `linotp` | LinOTP two-factor authentication, from env only: MISP refuses these settings while the plugin is off (LINOTPAUTH_ENABLED=true turns it on) |
| `oidc` | OidcAuth plugin, rendered into config.php when OIDC_ENABLE=true. The documented OIDC_* names map onto these (env.py ALIASES). role_mapper and scopes take JSON in env; scopes also takes a comma-separated list. |
| `ldap` | LdapAuth plugin, rendered into config.php when LDAPAUTH_ENABLE=true |
| `apache_auth` | ApacheSecureAuth (header auth with LDAP lookup), rendered into config.php when APACHESECUREAUTH_LDAP_ENABLE=true |

| `tests/k3s/misp-25.yaml` | MISP 2.5.50 from the MISP project's images (github.com/MISP/misp-docker): the hub-spoke suite's partner C, on the MariaDB of tests/k3s/mariadb.yaml and a Redis of its own. The suite puts the settings, in the names of those images, in the ConfigMap misp-25-env. A rebuild moves a tag, so the digests pin the images. No pod gets service links: misp-docker reads REDIS_PORT, which a link sets to tcp://<address> |
| `tests/k3s/oidc.yaml` | OIDC through the Keycloak of tests/k3s/keycloak.yaml (realm tests/keycloak-realm.json), on top of values.yaml for the integration and migration suites. No default organisation: the user lands in its Keycloak organisation's team or nowhere. |
